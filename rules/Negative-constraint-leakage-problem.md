# 输出纯净与元指令隔离规则

## 目的
防止任何“关于如何生成、修改、否决、比较内容”的信息进入最终交付物。
适用于：文档、代码、注释、配置、测试、提交信息、PR 描述、报告、方案、邮件等所有输出。

## 定义
- 元指令：用户对生成过程的约束、否定、否决、比较、修改要求、对话历史、未采用方案。
- 交付物：用户要求产出的最终内容。
- 污染：任何非最终规格的信息进入交付物。

## 强制规则
R1 元指令只作用于生成过程，不得进入输出。
R2 交付物只表达最终规格，不表达生成过程、修改历史、否决记录、对话上下文。
R3 收到否定时，只做内部删除/替换，不得在输出中写“不需要/没有/不包含/已移除/未采用/排除 X”。除非用户明确要求写入。
R4 优先正向白名单。把“不要 X”转为“只包含/使用/实现 Y”，输出只体现 Y。
R5 修正后必须从最终规格重写完整交付物；不得追加修正说明、对比说明、理由说明。
R6 禁止在输出中引用用户、对话、历史、之前版本、用户要求、AI 解释、自我指涉。
R7 代码注释、文档字符串、提交信息、PR 描述只描述当前实现、行为、技术约束，不描述对话、否决、未采用方案。
R8 文档只描述最终事实、步骤、规格，不描述编辑历史、否决项、比较项。
R9 输出前自检：扫描元讨论标记；若出现，静默删除并重写。不得在输出中承认或解释删除。
R10 例外：仅当用户明确要求写入变更记录或否决说明时，才可写，且必须放在单独指定区域，不得混入主体交付物。

## 禁止输出模式
- “不需要 X”“没有 X”“不包含 X”“已移除 X”“未采用 X”“排除 X”
- “用户说”“按你要求”“根据对话”“之前提到”“原来有”“改成”“已修改”
- “因为用户不要”“所以这里不放”“本版本没有”
- 在代码注释中写：对话、需求变更、否决理由、未采用模块
- 在文档主体中写：修改历史、否决记录、方案对比，除非明确要求

## 执行流程
1. 维护内部最终规格，不把否决项写进输出。
2. 收到否定：更新最终规格，执行删除/替换。
3. 从最终规格重新生成完整交付物。
4. 输出前扫描禁止模式。
5. 发现污染：静默删除，重写纯净版，不道歉、不解释、不回顾。

## 输出前检查清单
- [ ] 是否出现被否定项或非最终项？
- [ ] 是否出现元讨论、对话、历史、用户引用？
- [ ] 是否在解释修改，而不是交付最终内容？
- [ ] 能否用正向白名单替代否定描述？
- [ ] 是否应重写而非追加？
- [ ] 代码注释是否只描述当前代码行为？
- [ ] 文档是否只描述最终规格？

## 违反处理
发现污染：删除污染内容，按最终规格重写，只输出纯净交付物。
不解释，不道歉，不回顾对话。
