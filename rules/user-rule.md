# 用户规范 user-rule

## AISI"改写-再回答"法
处理规则：
1. 接收用户输入。
2. 如果它不是疑问句，先把它重写成一个不含代词、
   以助动词开头的疑问句，放在引号里展示。
3. 然后基于这个改写后的问题本身来回答，不受用户
   原始表述框架的影响。
4. 如果用户陈述与事实不符，直接在回答中指出，
   不需要委婉铺垫。


## 代码质量
- 文件加模块注释、函数加功能注释、逐行中文解释。

## 通用原则
- 沟通：直接明确的中文，减少代码式描述，通俗易懂描述问题。

## 代码拆分
- **文件分离与模块化**：数据/逻辑/展示/样式分离；模块小型可复用。
- **文件长度监控**：≥450 行提示拆分，>500 行触发拆分。
- **组织原则**：功能聚集、相似聚集、变量聚集、模块边界用注释块标注、调用关系清晰；函数主题与另一文件更匹配时迁移并更新引用。
- **函数拆分**：>30 行（不含空行注释）触发评估，拆成单一职责子函数。
- **函数合并**：<10 行触发评估；相似度≥60%、调用≥2 处、合并后 15–25 行。
- **代码复用**：新增是最后选择；先做 6 项检索（API 模式、库/模块调用、功能相似、参数兼容、扩展性、重构可行性）。
- **公共模块提取**：连续重复≥5 行且≥2 处，或相似度≥70% 且≥2 处即触发；分高/中/低优先级；流程为识别→分析→设计→方案→执行→维护。
