# 工作记忆维护

## 目的
长任务中实时沉淀关键信息与进度，避免遗漏用户诉求、重复已否决方案、或在中断后丢失上下文。

## 记忆文件
- 位置：`memory/`，每日一份：`memory/YYYY-MM-DD.md`。
- 当日文件不存在则新建；已存在则增量更新。
- 用 `write_to_file` / `replace_in_file` 维护。

## 记录内容（三节）
- **用户关键信息**：用户亲口提出的决策、偏好、约束、否决项，逐条一句话。工具结果（`bridge-chat-res`）属工具产物，不计入。
- **当前进度**：一句话现状 + 已完成 / 进行中。
- **待办与风险**：未决问题、下一步。

## 更新时机
- 用户发言后尽快更新，反映其新提出的重要信息。
- 出现关键决策、完成阶段、方向调整时更新。

## 置信度与重塑
记忆是尽力而为的记录，可能滞后或失真，引用时保持低置信度。发现与事实不符时以事实为准，并立即重写该条。

## 精简
- 单文件不超过 60 行；超出时合并同类项、删除失效条目，不新增分节。
- 一条一句话，不复述对话、不抄推理。
