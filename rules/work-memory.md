# 工作记忆维护

## 目的
长任务中实时沉淀关键信息与进度，避免遗漏用户诉求、重复已否决方案、或在中断后丢失上下文。

## 记忆形态：全部结构化存库
工作记忆**全部由后端 SQLite 记忆库承载**，不再用 Markdown 文件存储。

- 唯一权威：后端 SQLite 记忆库。
- 浏览器 / 本地不持久化记忆；读取一律走后端接口。
- 启动时把规则与节点精华摘要一次性加载进内存，接口读取优先走内存。

记忆分三个逻辑层次，同源互补：

- **原始层**：消息树节点，`blocks` 无损永久保留，是唯一权威。
- **蒸馏层**：从节点提取「结论 / 进度 / 关键词」，异步执行，只在原始内容之上叠加。
- **事件层**：用户发言为根，语义聚类成事件进化史，关键词交集建突触边；全自动运行。

## 每日记忆与错题本：也在库里
每日记忆与错题本属于结构化记忆的一部分，同样存在数据库 `notes` 表：

- `kind='journal'`：每日记忆条目，`day` 字段记日期（YYYY-MM-DD）。
- `kind='notebook'`：错题本条目，永久累积。

读写一律走接口，不写文件：

- 写入：`POST /memory/note`，参数 `{ kind, text, day?, node_id?, keywords? }`。
- 列举：`GET /memory/notes?kind=&day=`。
- 日期列表：`GET /memory/notes/days`。
- 删除：`POST /memory/note/delete`，参数 `{ note_id }`。

## 记忆的读写与检索接口

- **会话与节点**：会话读写（`/memory/conversation`）、节点读写（`/memory/node/<id>`、`/memory/set`、`/memory/list`、`/memory/delete`）。
- **检索（双接口互锁）**：
  - 接口 A 计划锚定：`POST /memory/plan`，纯写入计划原文。
  - 接口 B 验证式搜索：`POST /memory/search`，锚定验证 → 三路并行检索 → RRF 融合 + 关键词交集置信度。
- **分级**：`/memory/promote`（手动升级）、`/memory/strength`（查强度）、`/memory/decay/run`（触发衰减）。
- **事件**：`/memory/events`、`/memory/event/tree`、`/memory/event/merge`、`/memory/event/history`。
- **固化**：`/memory/solidify/rule`（升为规则文件）、`/memory/solidify/notebook`（写入错题本）。
- **可视化**：`/memory-graph`（力导向全景图 + 径向树视图）。

## 启动加载与自动维护

- **启动加载**：服务启动时调 `memory_loader.load_all()`，把规则与节点精华摘要读进内存；接口读取优先走内存。
- **自动维护**：消息入树后异步蒸馏，蒸馏完成自动建突触、给用户发言挂影子；
  后台调度周期性执行衰减计算与事件聚类，绝不在请求路径上执行。

## 规则程序化

`rule_enforce.py` 对**可机械判定**的规则做检查：写文件后回读、破坏性操作是否触碰真实数据、
输出禁用词扫描。

**语义性规则**（如「不得捏造用户发言」「先改写再回答」）仍由 AI 判断，程序只做注入强制与输出审计。

## 更新时机

- 用户发言后尽快更新，反映其新提出的重要信息。
- 出现关键决策、完成阶段、方向调整时更新。

## 精简

- 一条一句话，不复述对话、不抄推理。
- 优先保留 `P0/P1` 与 `[长期]`；`P3` 与 `[当日]` 可批量压缩或删。
