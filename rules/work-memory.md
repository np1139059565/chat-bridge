# 工作记忆维护

## 目的
长任务中实时沉淀关键信息与进度，避免遗漏用户诉求、重复已否决方案、或在中断后丢失上下文。

## 记忆文件
- 位置：`memory/`，每日一份：`memory/YYYY-MM-DD.md`。
- 当日文件不存在则新建；已存在则增量更新。
- 用 `write_to_file` / `replace_in_file` 维护。
- 单文件上限 300 行（可在本规则调整）；超出时合并同类项、删失效条目。

## 新建文件的初始化（必做，顺序固定）
1. **先提纯「总是」规则进头部**：把 rules 中所有 `[总是]` 规则的精髓压成几行，写在文件头部
   「## 常驻规则」节，避免换天后忘掉关键约束。
2. **再迁移昨日未完成**：读前一天记忆文件的「待办与风险」，把未完成项搬进新文件
   「## 待办与风险」，防止失忆。
3. 最后才开始记当天的新内容。

## 时间精度
- 文件头写完整日期与生成时间：`# 工作记忆 YYYY-MM-DD（HH:MM 起）`。
- 每条关键信息、每次进度更新都带时间戳 `HH:MM`，便于还原先后与判断新鲜度。

## 记录内容（三节）
- **用户关键信息**：用户亲口提出的决策、需求、偏好、约束、否决项，逐条一句话，前置时间戳。
  - **记录格式（区分类型，不要一刀切）**：一律**先逐字保留用户原句**，再按类型决定是否附转写疑问句。
    - **用户对代码 / 实现的陈述句** → 原句在前，其**后**另起一行附缩进的转写疑问句
      （如原句「这里用 X 实现」→ 附注「此处是否用 X 实现？」），便于下次带着疑问去核对代码。
    - **用户的需求 / 决策 / 偏好 / 否决项** → 只保留原句，**不转**疑问
      （如「用户要求按钮自动截图回传」），需求是明确指令，转成疑问会丢确定性。
  - **为何原句必须留存**：疑问句是二次转写，若用它替换原句，一旦转写失真便无从对质；
    保留原句可随时核对，也是防止凭空生成语义的底线（昨日「外部卡片」误记即为此类反面教训）。
  - 工具结果（`bridge-chat-res`）属工具产物，不计入。
- **当前进度**：一句话现状 + 已完成 / 进行中，逐条带时间戳。
- **待办与风险**：未决问题、下一步；每条标优先级（见下）。

## 置信度与优先级（每条可标，用于自动调节重要程度）
- **置信度**：`[高]` / `[中]` / `[低]`，标注该条与事实的吻合把握；与事实不符时以事实为准并重写。
- **优先级**：`P0`（阻塞 / 必须马上做）、`P1`（重要，本轮内做）、`P2`（可延后）、
  `P3`（长期 / 备忘）。
- **长期记忆**：跨天仍有效、反复用到的条目标 `[长期]`，迁移时优先搬运；
  只对当天有效的标 `[当日]`，可随时间淘汰。
- **自动调节**：多次被引用 / 验证为真的条目，置信度上调、优先级可升；
  久未使用或已失效的条目，降级或删除。

## 错题本（永久记忆，非规则）
- 位置：`memory/error-notebook.md`。它不属于规则（不参与 System Prompt 规则列表、不主动读取）。
- 性质：永久记忆。与每日工作记忆不同，它跨天长期有效、持续累积。
- 读取时机：**卡住无思路、或犯下严重错误时**，才去翻阅；平时不读。
- 用途：记录新犯的错误；查看历史上同类错误是如何处理的、当时怎样才让用户满意。
- 维护：犯下值得记的严重错误时追加；同 `write_to_file` / `replace_in_file`。

## 更新时机
- 用户发言后尽快更新，反映其新提出的重要信息。
- 出现关键决策、完成阶段、方向调整时更新。

## 精简
- 一条一句话，不复述对话、不抄推理。
- 优先保留 `P0/P1` 与 `[长期]`；`P3` 与 `[当日]` 可批量压缩或删。
