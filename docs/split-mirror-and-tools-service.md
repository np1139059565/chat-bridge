# 拆分方案：翻译员 与 工具服务

> 状态：**方案定稿，待实施**。本文档是唯一规格来源，实施过程中一切取舍以此为准。
> 实施采用多 AI 分工，代码由执行方编写，由需求分发方审核后合入。

## 一、核心定位

系统由两个角色组成，边界清晰、互不越界：

```
工具服务 = 标准接口 + 本地工具 + 用户指令 + 公共服务（语音、投递队列、记忆）
翻译员   = 网页 AI 的方言适配器（装在浏览器里，一个本体 + 多套语言包）
```

**一句话**：工具服务只说普通话，翻译员负责方言。工具服务从头到尾不知道「网页 AI」这种生物存在。

### 1.1 两类客户端的等价性

对工具服务而言，下面两者是同一件事，都是「一个注册过的客户端」：

| 客户端 | 连上来做什么 |
|---|---|
| 翻译员（浏览器里的抽屉） | 把网页 AI 的方言翻成标准调用 |
| 任意标准 API 客户端 | 直接按标准格式调用 |

工具服务不区分它们，也不解释它们自报的标识代表哪个网站。

### 1.2 翻译员的构成

翻译员是**一个本体**，不是「每个网站一个翻译员」：

| 组成 | 作用 | 归属 |
|---|---|---|
| 方言处理函数 | 每个网站输入框结构不同、写入方式不同、发送触发不同，各自一套处理代码 | 翻译员 |
| 语言包 | 该站点的元素选择器、容器特征等配置数据 | 翻译员所有，寄存于工具服务 |
| 提示词拼装 | 把标准提示词加方言说明交给网页 AI | 翻译员 |
| 调用解析与回传 | 代码块 ↔ 标准 `tool_calls` | 翻译员 |
| 卡片语义与执行状态 | 建卡、执行、已执行记录 | 翻译员 |
| 网页原文存储 | 网页上长什么样就存什么样 | 翻译员 |

换一个网站，只需换一套语言包与一支方言处理函数，本体不变。

| 特性 | 归属 | 落点 |
|---|---|---|
| 本地工具（文件读写、命令执行、搜索等） | 工具服务 | 参数声明改为标准 JSON Schema |
| 工具列表 | 工具服务给数据，翻译员转文字 | 服务端按标准 `tools` 数组提供 |
| 技能清单与内容 | 工具服务给数据，翻译员转文字 | 同上 |
| 规则清单与内容 | 工具服务给数据，翻译员转文字 | 同上 |
| System Prompt 主体 | 工具服务 | 身份 + 规则 + 技能 + 先查参数通则 |
| 方言说明（调用格式、回传格式、朗读约定） | 翻译员 | 工具服务不感知 |
| 方言处理函数（输入框定位、写入方式、发送触发） | 翻译员 | 随网站各异 |
| 语言包（站点元素配置） | 翻译员所有，工具服务保管 | 存于客户端注册信息，服务端不解释字段 |
| 记忆 | 工具服务 | 不变 |
| 会话记录（标准格式） | 工具服务 | 标准 `messages` 历史 |
| 会话记录（网页原文 + 卡片状态） | 翻译员 | 工具服务不感知 |
| 指令（全部类别） | 工具服务 | 含内置、自定义、组合、各客户端注册的指令 |
| 语音合成 | 工具服务 | 公共服务，任何客户端可调 |
| 投递队列 | 工具服务 | 公共服务，任意两端可对接 |
| 全局配置 | 工具服务 | 单一真源 |
| 推送通道凭证 | 工具服务 | 不变 |
| 站点/连接隔离 | 工具服务 | 只认连接标识，不解释语义 |
| 工具调用格式解析 | 翻译员 | 代码块 ↔ 标准 `tool_calls` |
| 卡片语义、执行状态、已执行签名 | 翻译员 | 工具服务只负责投递，不管语义 |
| 自动执行、粘贴守卫、风控恢复 | 翻译员 | 页面操作，工具服务无法触碰 |

## 三、工具服务对外提供什么

### 3.1 标准对话接口

`POST /v1/chat/completions`

| 能力 | 支持 |
|---|---|
| 多轮对话 | 是，服务端记录完整标准会话 |
| 并行工具调用 | 是，一次回复可含多个 `tool_calls` |
| 工具角色回灌 | 是 |
| 流式输出 | **否**。请求携带 `stream: true` 时明确返回错误，不静默降级 |

### 3.2 标准 System Prompt

内容边界：**身份 + 规则 + 技能清单 + 「调用前先查参数」通则**。

不含方言说明、不含朗读约定、不含任何只在网页 AI 场景成立的内容。

### 3.3 本地工具

工具定义与执行留在工具服务。参数声明统一为标准 JSON Schema 格式：

- 容器由数组改为对象：`{"type": "object", "properties": {...}, "required": [...]}`
- 必填项由每项的 `required` 布尔改为顶层 `required` 数组
- 联合类型使用 `anyOf` 表达（`read_file` 的 `path` 即采用此写法）

迁移逐项登记于 `docs/tool-schema-migration.md`，全部勾选后方视为完成。

### 3.4 用户控制指令

指令定义**全部存于工具服务**，限用户使用，不进入 AI 对话流。

| 类别 | 定义位置 | 执行位置 |
|---|---|---|
| 服务能力类（清空会话、卡片操作、重启、语音、记忆、Prompt 等） | 工具服务 | 工具服务 |
| 界面行为类（面板开关、会话切换、重新解析等） | 工具服务 | 下发抽屉执行 |
| 各客户端注册的指令 | 工具服务（客户端注册时登记） | 客户端 |
| 自定义指令 / 组合指令 | 工具服务 | 工具服务或客户端 |

注册机制沿用 `docs/external-command.md` 既有规范，不另立一套。

**指令回执走独立通道，绝不进入 AI 对话流**，指令执行结果不流向 AI。

### 3.5 公共服务：语音合成

`POST /api/voice/tts` 类标准接口：传入文本，返回音频。

工具服务只负责「文本 → 音频」，不关心这段文本是正文还是朗读稿，也不关心客户端为什么需要它。

### 3.6 公共服务：投递队列

原「外部卡片」升级为**通用投递队列**，与语音同级，任何两端都可对接：

| 链路示例 | 用途 |
|---|---|
| 网页 AI → 翻译员 → 投递队列 → 调试扩展 | AI 指挥页面调试工具 |
| 推送通道 → 投递队列 → 翻译员 → 网页 AI | 手机消息进入网页 AI |

接口保持「发送即结束」语义：登记即返回，不阻塞等待结果；接收方轮询取走并回执「已展示」。

队列本身不含网页语义，不认识「卡片」这个概念的内涵，只负责把一段载荷从一端送到另一端。

### 3.7 客户端注册与自定义配置

工具服务提供客户端注册接口。客户端注册时携带：

| 字段 | 说明 |
|---|---|
| 客户端标识 | 服务端原样保存，只用于路由，不解释其含义 |
| 自定义配置 | 客户端私有数据（如某站点的语言包），服务端**原样保管、原样下发、不校验字段** |
| 可执行指令声明 | 该客户端能执行哪些指令 |

服务端对该自定义配置的职责边界：存进去、取出来、保持原样。不做字段校验、不做结构清洗、不解释语义。

设置页的「网页 AI 站点配置」界面保留，定位为**编辑客户端的注册信息**，读写该自定义配置。

### 3.8 记忆与会话

记忆、标准会话历史均由工具服务持有。工具服务不感知卡片状态这类网页场景概念。

### 3.9 保留 POST /tool

两个接口职责不同，均保留：

| 接口 | 谁决定调什么 | 用途 |
|---|---|---|
| `POST /tool` | 调用方 | 低层执行器，直接执行单个工具，调试入口 |
| `POST /v1/chat/completions` | 模型 | 标准对话接口 |

## 四、翻译员负责什么

### 4.1 方言处理函数

每个网站一套，负责：

- 定位输入框（各站结构不同，`textarea` / `contenteditable` 混杂）
- 写入文本（原生 setter / 模拟粘贴事件，按输入框类型分流）
- 触发发送（回车 / 点按钮 / 等待就绪）
- 判定生成态（按钮文案 / 禁用标记 / 输出容器）

这些代码只在浏览器里有效，工具服务无法执行。

### 4.2 语言包

该站点的元素选择器与容器特征，以数据形式存在。

语言包由翻译员所有，寄存在工具服务的客户端注册信息里，服务端不解释其内容。翻译员启动时取回，用于适配当前站点。

### 4.3 提示词拼装

翻译员从工具服务取回标准 System Prompt，再追加：

- 工具调用格式说明（代码块怎么写）
- 结果回传格式说明
- 语音朗读稿约定（若开启语音）

拼接完成后交给网页 AI。

### 4.4 调用解析与结果回传

| 方向 | 做什么 |
|---|---|
| 网页 AI → 工具服务 | 把 `bridge-chat-call` 代码块翻译为标准 `tool_calls` 送入标准接口 |
| 工具服务 → 网页 AI | 把标准 `tool` 消息翻译为 `bridge-chat-res` 代码块贴回对话 |

网页 AI 单线程输出，同一轮只可能有一个调用块；出现多个时由翻译员拦截告警，不送入工具服务。

### 4.5 卡片语义与执行状态

建卡、执行、已执行签名、刷新恢复，全部由翻译员负责。工具服务的投递队列只负责把载荷送到。

### 4.6 网页原文存储

网页上长什么样就存什么样，含卡片状态。刷新不丢、关标签页不丢。

唯一清理入口是抽屉设置页的手动清空或删除；不设过期时间、不设条数上限自动淘汰。

## 五、通道与数据边界

### 5.1 工具与指令严格分离

| | 工具 | 指令 |
|---|---|---|
| 谁发起 | AI | 用户 |
| 结果去哪 | 回到 AI 对话流 | 回到发起指令的用户 |
| 存哪 | 工具服务 | 工具服务 |

推论：标准接口的 `tool` 角色消息只承载工具结果，不得承载指令回执。

### 5.2 两份会话记录

同一段对话在两处形态不同、职责不同：

| 记录 | 归属 | 形态 | 用途 |
|---|---|---|---|
| 标准会话历史 | 工具服务 | 标准 `messages` | 供标准接口与记忆使用 |
| 网页原文记录 | 翻译员 | 网页原样 + 卡片状态 | 供界面呈现与刷新恢复 |

两者不是冗余副本，也不是二选一。

### 5.3 连接隔离

工具服务维护「连接标识 → 消息路由」，只保证发给某个标识的消息只回到该标识，不解释标识代表哪个网站。

## 六、接口规格要点

### 6.1 工具结果的内容约定

标准 `tool` 消息只有 `content` 一个字符串字段。现有错误体系（`errorType` / `origin` / `hint` / `available`）整套以 JSON 字符串形式放入 `content`，客户端按约定还原。

不额外增加成功/失败布尔字段，成败由 `content` 内 JSON 判断。

该约定写入接口文档。

### 6.2 并发与超时

沿用工具服务既有的工具池与超时机制，接口层不另建一套。

### 6.3 鉴权

不设鉴权，服务仅监听 `127.0.0.1`。

配置注释中须写明：改为监听 `0.0.0.0` 意味着局域网内任何设备均可调用本地工具执行命令。

## 七、分阶段计划

### 阶段 1a：工具服务学会标准接口

范围：

1. `POST /v1/chat/completions`（标准 messages / tools / tool_calls / 非流式）
2. 标准 System Prompt 生成
3. 标准会话历史存储
4. 语音合成独立接口
5. 客户端注册接口（含自定义配置原样保管）
6. 投递队列改造为通用服务（接口语义不变，命名与定位中性化）
7. 指令统一收归服务端管理

**验收**：脚本化自测，覆盖正常对话、工具调用、工具结果回灌、多轮、错误回传、客户端注册与配置取回六类场景。

### 阶段 1b：参数声明迁移

范围：把全部工具参数声明改为标准 JSON Schema，逐项勾选 `docs/tool-schema-migration.md`。

**验收**：迁移文档全部勾选，全部测试通过，`read_file` 的单路径与多路径两种调用均可用。

### 阶段 2：翻译员改造

范围：

1. 提示词拼装改为「取回标准提示词 + 追加方言说明」
2. 工具调用解析改为翻译标准 `tool_calls`
3. 工具结果回传改为翻译标准 `tool` 消息
4. 语言包改为从客户端注册信息取回
5. 指令执行端对接服务端下发的指令定义

**验收**：网页 AI 全流程可用，行为与改造前一致。

### 阶段 3：删除旧链路

**触发时机**：阶段 2 验收通过的当天。

范围：

1. 翻译员里旧的建卡直调工具执行路径
2. 工具服务里只为网页 AI 写的字段与分支
3. `remote_bridge/` 下经取证确认无用的遗留

**前置条件**（三条同时满足才动手）：

1. 新链路在真实使用中跑过一段时间，未出现执行错乱或结果丢失
2. 刷新恢复、卡片去重、自动回传、多站点隔离、语音、记忆六项在新链路上逐一验证通过
3. 旧路径已无调用方

## 九、实施与审核流程

| 角色 | 职责 |
|---|---|
| 需求分发方 | 维护本文档为唯一规格来源；拆分任务并写明验收标准；审核执行方提交的代码；把控阶段边界与合入节奏 |
| 执行方 | 按分配的任务范围写代码；提交前自测；按约定格式提交改动 |

**审核口径**：

1. 改动是否落在任务范围内，有无越界触碰未分配的文件
2. 是否符合本文档的归属划分
3. 测试是否覆盖新增行为
4. 是否通过既有质量闸与测试套件
5. 提交信息是否只描述改动本身

**合入节奏**：一个任务一次提交，验证通过后合入；不合入半成品，不留长期并存的双轨。
