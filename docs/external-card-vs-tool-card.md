# 外部卡片 vs 普通工具卡片：差异对照

用于评估「外部卡片要不要进一步向普通卡片靠拢」。
本文只描述现状差异与可选同步项，供挑选。

---

## 一、一句话区别

- **普通工具卡片**：网页 AI 发起的「一次工具调用」，卡片负责执行并把结果回传网页 AI。
- **外部卡片**：本地扩展（调试抽屉）发起的「一条请求」，卡片负责把请求送到网页 AI，送完即结束。

---

## 二、差异全清单

### 1. 发起方

- 普通卡片：网页 AI（输出工具调用代码块）。
- 外部卡片：本地扩展 / 抽屉（`POST /api/cards`）。
- 影响：外部卡片需要一个「服务端登记 + 插件轮询」的额外通道。

### 2. 传输通道

- 普通卡片：`POST /tool` 同步阻塞，结果原路返回。
- 外部卡片：`POST /api/cards` 登记 → 插件 `GET /api/cards/pending` 取 → 插件 `POST /api/cards/<id>/reply` 回。
- 影响：外部卡片依赖插件轮询节奏（1 秒），存在最多约 1 秒投递延迟。

### 3. 是否等待结果

- 普通卡片：执行后**等待**结果，结果回填并自动回传网页 AI。
- 外部卡片：发送即结束，**不等待**网页 AI 回复（本次已改）。
- 影响：外部卡片不会因网页 AI 未回复而超时；后续沟通改为 `push_message` 主动推送。

### 4. 结果形态

- 普通卡片：有 `result` / `error`，可展开查看，可复制结果。
- 外部卡片：结果是「已投递」确认；真正的任务产出体现在网页 AI 的 `push_message` 与最终回答里。

### 5. 状态机

- 普通卡片：`pending → running → done / error`（含执行/回传两个倒计时阶段）。
- 外部卡片：`pending → done`（发送阶段有倒计时）。
- 影响：外部卡片缺少 `running` / `error` 的完整状态语义。

### 6. 按钮

- 普通卡片：执行 / 重新执行、跳过、复制结果。
- 外部卡片：发送 / 重新发送、复制结果。
- 影响：外部卡片没有「跳过」。

### 7. 时序位置

- 普通卡片：内嵌在对话流里（跟随其所在消息）。
- 外部卡片：原先一律置顶；现与文字消息共用统一时间戳 `_ts`，统一排序。
  规则：每条消息与每张外部卡片都带 `_ts`（毫秒），渲染时按 `_ts` 统一排序，无任何类型特殊处理。
- 影响：三者（文字消息 / 工具卡片 / 外部卡片）已完全统一时序，工具卡片是消息内的代码块，随其消息一并渲染。

### 8. 持久化

- 普通卡片：`conv.cardMap` 持久化。
- 外部卡片：原先在组件顶层、不持久化；本次改为 `conv.externalCards` 持久化。
- 影响：两者在「按会话隔离 + 持久化」上已统一。

### 9. 历史卡片管理

- 普通卡片：在「历史卡片管理」中列出。
- 外部卡片：原先不在；本次已并入同一列表（`sortedHistoryCards` 合并两者）。

### 10. 来源标识

- 普通卡片：标题为「工具调用 · 工具名」。
- 外部卡片：标题为「外部卡片 · 标题」，另有 `external` 徽标与左侧色条。
- 影响：视觉上仍可一眼区分来源（这是刻意的）。

### 11. 自动开关语义

- 普通卡片：勾「自动」→ 倒计时自动执行，执行完再倒计时自动回传。
- 外部卡片：勾「自动」→ 倒计时自动发送，发送后结束。
- 影响：外部卡片没有「自动回传」这一步。

### 12. 参数展示

- 普通卡片：展示 `parameters` JSON（工具入参）。
- 外部卡片：展示 `content`（发送给网页 AI 的正文）。
- 影响：两者都用 `params-json` 样式，语义不同。

### 13. 与网页 AI 的协议

- 普通卡片：走 `bridge-chat-call` / `bridge-chat-res`。
- 外部卡片：走 `debug-chrome-req` 信封（输出信封已废弃）。

---

## 三、可选的同步项（供挑选）

| 选项 | 内容 | 收益 | 成本 |
|---|---|---|---|
| A | 给外部卡片补 `running` / `error` 状态与错误展示 | 状态机与工具卡片完全一致 | 需定义外部卡片何时进入这些状态 |
| B | 给外部卡片补「跳过」按钮 | 按钮集合一致 | 语义需明确（跳过=不发送） |
| C | 外部卡片锚点改用真实时间戳（消息也带时间戳） | 时序更精确 | 需给镜像消息补时间戳，改动面较大 |
| D | 外部卡片也走「执行 → 回传」两步 | 与工具卡片统一 | 与「发送即结束」目标相悖，不建议 |
| E | 统一参数区标题（如都叫「内容」） | 视觉更一致 | 会削弱语义区分，收益有限 |
| F | 去掉 external 徽标 / 色条 | 外观完全一致 | 失去来源区分，不建议 |

> 已完成的同步：时序融入对话流（7）、持久化（8）、历史卡片管理（9）、按会话隔离。
> 保持的差异：3、4、5、6、10、11、13 —— 这些源于「外部卡片是请求、工具卡片是调用」的本质不同。
