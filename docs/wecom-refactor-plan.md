# 企业微信通道重构方案

## 一、目标

企业微信通道的行为与网页版机器人完全一致：文字、图片、文件、语音、
图文消息全部可用，且消息形态与其它通道等价。

## 二、铁律

**除「接收消息」与「发送消息」这一瞬间的协议差异外，各通道的消息体必须完全一致。**

- 一条消息进入系统后，无论来自哪个通道，转成卡片投给网页 AI 的形态必须相同：
  图片是图片卡片、文件是文件描述、文本是文本。
- 一条 AI 回复出系统时，各通道的消息内容必须相同，只在「怎么发出去」这一步按协议适配。
- 能力不足的通道可以不推，但必须显式声明不支持，不能默默降级成另一种形态。

判断标准：把同一份内容喂给任意两个通道，除协议编码外，用户侧看到的东西应当等价。

## 三、通道差异的边界

允许存在差异的只有三处：

1. **连接方式** —— QQ 走 WebSocket 事件、微信走长轮询、企业微信走 WebSocket 长连接。
2. **消息编码** —— 各平台的帧结构、字段名、长度上限不同。
3. **能力声明** —— 某平台不支持的媒体类型，显式声明不支持。

其余一切（内容提取、合并策略、去重、重试、语音合成时机、卡片形态）必须共用同一套实现。

## 四、企业微信必须使用主动推送

企业微信不依赖被动回复窗口（`needs_window = False`），因此：

- 所有出向消息（文本 / 图片 / 文件 / 语音）一律走主动推送。
- 被动回复凭证（`req_id`）不参与出向发送，相关逻辑全部剔除。
- 不保留「优先回复、失败再推送」的双通路，双通路会让故障难以定位。

## 五、已查出的问题清单

### 5.1 出向发送

| 编号 | 问题 | 影响 |
|---|---|---|
| O1 | 回复帧把 `markdown` 与 `stream` 混装在同一消息体 | 平台判 `errcode=40008 invalid message type` 直接拒收 |
| O2 | 发送只看 socket 是否抛异常，不校验平台 `errcode` | 拒收时仍返回成功，故障不可见 |
| O3 | 文本与媒体优先走被动回复凭证 | 一条凭证只能回一条，多张图时后续全被跳过 |
| O4 | 语音在推送正文前同步合成 | 用户要等整批语音合成完才看到文字，与 QQ 行为不一致 |
| O5 | 语音补推函数硬编码调用 QQ 的发送实现 | 企业微信传入自己的客户端必然失败 |

### 5.2 媒体收集

| 编号 | 问题 | 影响 |
|---|---|---|
| M1 | 文件从 `blocks` 里找，实际存放在消息的 `files` 字段 | 文件永远收集不到 |
| M2 | 语音预合成结果 `voice_paths` 收下但从未使用 | 语音永远取不到路径 |
| M3 | 图片只认 dataURL 与 http 地址，相对接口地址被丢弃 | 部分图片无法发出 |

### 5.3 入向接收

| 编号 | 问题 | 影响 |
|---|---|---|
| I1 | 图片下载后只把本地路径当文本投给网页 AI | 模型看不到图片内容，等于没收到 |
| I2 | 指令回执立即用被动回复发出 | 与主动推送双通路并存，行为不一致 |

### 5.4 公共层

| 编号 | 问题 | 影响 |
|---|---|---|
| P1 | 新推送管线从不写待推缓存 | 失败消息无法补回，QQ 的补回机制同样空转 |
| P2 | 企业微信未实现 `prepare_items` | 失败消息滚出可见区后永久丢失 |

## 六、改造清单

### 阶段一：出向发送统一到主动推送

- [x] 回复帧按 `msgtype` 二选一，不混装
- [x] 发送等待平台应答并校验 `errcode`
- [x] 文本走主动推送
- [x] 媒体走主动推送
- [x] 剔除路由层的回复凭证逻辑
- [x] 剔除网关层的回复凭证透传
- [x] 补死锁保护：回调线程内发送不等应答

### 阶段二：媒体收集对齐

- [x] 文件改从消息的 `files` 字段读取
- [x] 语音改用锁外预合成的结果
- [x] 图片支持相对接口地址解析

### 阶段三：入向对齐网页版

- [x] 图片转 dataURL 投图片卡片，由前端贴进输入框
- [x] 文件以卡片形式投递，卡片正文写明本地路径与体积
- [x] 语音入向与文件同构，同样以卡片投递

### 阶段四：公共层补齐

- [x] 新管线写入待推缓存
- [x] 企业微信实现 `prepare_items`
- [x] 逐条去重记账：企业微信走合并推送分支，逐条 `push_one` 不在调用路径上，本条以合并分支为准

### 阶段五：验证

- [ ] 文本多次发送均能收到
- [ ] 图片能收到并显示
- [ ] 文件能收到并下载
- [ ] 语音能收到并播放
- [ ] 图文消息（文字 + 图片）能合并成一条收到
- [ ] 用户发图片，模型能看到图片内容
- [ ] 发送失败时日志明确记录 errcode

## 七、验收标准

- 同一段 AI 回复，QQ 与企业微信收到的内容形态一致。
- 同一条用户图片，两个通道都能让模型真正「看到」图片。
- 发送失败时，日志能直接给出平台错误码与原因。
- 企业微信模块内不再出现 `req_id` 相关的发送分支。
