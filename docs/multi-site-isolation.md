# 多网页 AI 并存的隔离机制

一台电脑同时开多个网页 AI（千问 / 元宝 / Kimi / DeepSeek / GLM …）时，
需要保证各路消息与指令不互相串台。本文说明隔离是怎么做的、边界在哪。

## 一、三层隔离键

| 层级 | 隔离键 | 管什么 |
|---|---|---|
| 记忆与存档 | `site_key`（站点 id） | 消息树、会话存档、卡片执行签名 |
| 抽屉本地缓存 | `site_key` + `conv_id` | 键名 `aiMirrorConv_<site>__<conv>` |
| 手机网页端 | `site_key` | 收件箱消息、站点切换器 |
| 指令与卡片投递 | `page_url`（页面地址） | 指令卡片只投给指定页面的抽屉 |
| QQ / 企微通道 | `site_key`（按通道绑定） | 每条通道只看自己绑的站点 |

**为什么两种键并存**：`site_key` 解决「跨站混流」，页面关闭后历史仍在；
`page_url` 解决「同站多开」，能把指令精确投给某个标签页。

## 二、页面接管（/pages、/page）

全局只有一个「当前接管页面」，影响所有未绑定通道的指令投递。

| 指令 | 说明 |
|---|---|
| `/pages`（别名 `/pg`） | 列出在线页面，标出当前接管项 |
| `/page <序号>` | 按序号接管 |
| `/page <地址片段>` | 按片段匹配，**有歧义时报错不猜** |
| `/page off` | 取消接管，指令广播给所有页面 |

在线页面表由抽屉轮询自动登记（`/api/cards/pending` 与 `/api/commands/pending`
的 `page` 参数），90 秒无心跳视为离线。**内存态，重启后清空**。

## 三、通道绑定（/bind）

QQ 与企微都是单窗口，若不加绑定，各站回复会混进同一个聊天窗口。
绑定后「QQ 只跟 DeepSeek、企微只跟 GLM」，两者互不干扰。

| 指令 | 说明 |
|---|---|
| `/bind` | 查看当前通道的绑定与可选站点 |
| `/bind deepseek` | 把**当前这条通道**绑到 deepseek |
| `/bind off` | 解除当前通道的绑定 |

**绑定作用域是「当前通道」**：在 QQ 里敲就绑 QQ，在企微里敲就绑企微。
这是与 `/page` 的关键区别——`/page` 是全局的，`/bind` 是分通道的。

绑定持久化在运行时配置的 `channel_bindings` 键（本机偏好，不入库），重启后保持。

### 优先级

指令投递时按以下顺序解析目标页面：

1. **通道绑定的站点** → 该站点当前在线的页面（接管页优先，否则第一个）
2. **全局接管页**（`/page` 设的）
3. 都没有 → 不限页面（任何页面的抽屉都能取，旧行为）

通道绑定优先于全局接管，否则无法同时满足「QQ 跟 A、企微跟 B」。

### 推送侧过滤

| 通道状态 | 接收范围 |
|---|---|
| 未绑定 | 全部站点（旧行为，不改变现有用法） |
| 已绑定 | 只接收该站点的消息 |
| 已绑定 + 消息无站点标记 | 仍接收（避免丢历史数据） |

## 四、手机网页端

页面顶部有站点切换栏，列出所有已配置站点：

- 有在线页面的站点带绿点
- 当前选中的高亮
- 点另一个站点 → 整页重载

**为什么整页重载**：局部重置要处理游标、已渲染 DOM、去重集合、倒计时状态好几处，
漏一处就是脏数据。整页重载虽粗暴，但不可能漏。选择记在 `localStorage`。

收件箱的 `site` 参数三态语义：

| 传入 | 行为 |
|---|---|
| 不传（`None`） | 不过滤，兼容旧调用 |
| 空串 `""` | 只返回无站点标记的历史消息 |
| 非空 `"qianwen"` | 只返回该站点消息 |

## 五、已知限制

1. **接管状态不持久化**：服务重启后 `/page` 的接管丢失，需重新设置。
   理由：页面在线与否随标签页开关变化，持久化一个「接管某个已关闭页面」的
   状态反而更容易出问题。通道绑定（`/bind`）则持久化，因为它绑的是站点而非页面。

2. **站点 id 与域名片段靠映射表对应**（`glm → chatglm`）。新增站点若 id 与域名
   差得远，需在 `web_bridge/__init__.py`、`routes/web.py`、`core/channel_binding.py`
   三处的 `hints` 表里各补一行。**这是已知重复，等站点再多考虑抽公共。**

3. **同一通道不能同时跟多个站点**：`/bind` 一次只绑一个，绑新的会覆盖旧的。
   需要「QQ 同时看两个站」目前不支持。

## 六、排查口径

| 现象 | 先看什么 |
|---|---|
| 指令发了没反应 | 该通道是否绑了别的站点；`/pages` 看目标页是否在线 |
| 手机端看不到消息 | 站点切换器是否选中了正确的站 |
| 两个站消息混在一起 | 通道是否未绑定；`/bind` 查看 |
| 消息发出去了但没到 AI | 目标页面是否在前台；该页抽屉是否在线 |
