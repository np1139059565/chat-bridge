# 外部卡片规范（chat-bridge）

> 适用对象：向网页 AI 投递任务的外部工具（如调试扩展抽屉）。
> 本文规定外部卡片的信封结构、投递语义与渲染规则。

---

## 一、什么是外部卡片

外部卡片是「外部工具主动联系网页 AI」的载体。用户在扩展抽屉里输入需求、
附加已选元素，提交后组装成一张外部卡片，发往网页 AI 处理。

与工具卡片的区别：工具卡片是 AI 调用工具后生成的执行记录；
外部卡片是用户从扩展侧主动发起、投给 AI 的任务入口。

---

## 二、信封结构

外部卡片以信封结构发往网页 AI：

```json
{
  "type": "external-call",
  "nonce": "唯一标记",
  "request": "任务正文",
  "source": "qq",
  "openid": "用户标识",
  "msg_id": "消息标识",
  "page_url": "页面地址"
}
```

| 字段 | 说明 |
|---|---|
| `type` | 固定 `external-call`，用于识别 |
| `nonce` | 本次投递唯一标记 |
| `request` | 任务正文（用户诉求） |
| `source` | 来源渠道，如 `qq` |
| `openid` | 来源用户标识 |
| `msg_id` | 来源消息标识 |
| `page_url` | 关联页面地址 |

---

## 三、角色语义（重要，勿混淆）

会话中存在三类消息来源，判定靠 `msgSource` 字段：

| 来源 | msgSource | 是否算用户发言 |
|---|---|---|
| 用户网页亲口说 | `user` | 是 |
| 工具结果（`bridge-chat-res`） | `tool` | 否，属工具产物 |
| 外部卡片（`external-call`） | 归入 `user` | **是** |

要点：
- 工具结果（`bridge-chat-res`）是工具产物，**不计入**用户发言，也不写入工作记忆的「用户关键信息」。
- 外部卡片**算用户发言**。来源渠道（如 QQ）不影响该判定。
- 此语义曾出过错（曾擅自认定「外部卡片不算用户发言」），改动前必须核对用户原话。

---

## 四、投递语义

- **发送即结束**：外部卡片投递给网页 AI 后即结束，**不等待回传**。
- 登记即返回，卡片入列即 `POST /api/cards/<id>/delivered` 确认已展示，此后不再投递。
- 任务进展、结论与方案，由网页 AI 通过 `push_message` 工具**主动推送**给用户。

---

## 五、存储与渲染

- 外部卡片存 `conv.externalCards`，**按会话隔离**并持久化。
- 带 `anchorKey`（消息树 key）：渲染时按锚点插入到对应消息之后；
  锚点不在当前列表时放到末尾。
- 镜像区会跳过已处理且无消息本体的卡片，避免与消息本体重复显示。

---

## 六、投递方（扩展侧）约定

- 组装信封 → 提交工具服务 → 工具服务渲染卡片并自动发送至网页 AI。
- 内容脚本不直接发网络请求，一律走 `proxyFetch`（见开发指南 3.6）。
- 投递后不轮询回执，等 AI 用 `push_message` 联系。
