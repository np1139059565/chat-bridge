# 记忆机制改进方案（提案 v2·待审批）

> 状态：**提案**。本文档只描述拟议方案，未改动任何规则文件。
> 审批方式：对五个机制各报一个编号（如「1A 2A 3A 4A 5A」），另定第 6 项。

## 一、背景与诊断

现有 `rules/work-memory.md` 提供了记忆文件的基本骨架（每日一份、三节结构、时间戳、优先级、置信度），
但实践中暴露出三个病灶。以下为对 `memory/2026-10-04.md` 的只读诊断结果。

### 病灶 1：待办只增不减

- 现状：当日文件 220 行，`## 待办与风险` 节含 **24 条**待办，其中多条为当日上午的「待验证」项，长期未清。
- 根因：规则仅规定「P3 与 [当日] 可批量压缩或删」，未规定「完成即清」「超期即清」「总数上限」。
- 后果：待办节持续膨胀，真实待办被旧项淹没。

### 病灶 2：任务进度未及时更新

- 现状：进度记录绑在「用户发言后尽快更新」这一触发点上。
- 根因：实际工作节奏为「连续多个工具调用」；用户长时间不发言时，进度迟迟不写。
- 后果：中断后无法还原进度；跨天迁移时信息缺失。

### 病灶 3：无记忆固化升级规则

- 现状：规则含「多次被引用 / 验证为真的条目，置信度上调、优先级可升」一句。
- 根因：该句无阈值、无具体操作、无执行时机，实际无法执行。
- 后果：反复验证有效的经验沉淀不下来；错题本与规则库得不到来自日记的补充。

## 二、拟议机制（逐项审批）

### 机制 1：进度写入，由「用户触发」改为「动作触发」

- **1A（推荐）**：每完成一个可交付单元（提交一次、修完一个缺陷、完成一次诊断）即写一行进度，不等用户发言。
  - 好处：进度实时，天然带时间戳与提交号。
  - 坏处：写入更频繁，需约束单行长度（建议 ≤ 80 字）。
- **1B**：维持现状（靠用户发言触发）。
  - 好处：写入少。坏处：即当前问题。

### 机制 2：待办生命周期，加「保质期」

- **2A（推荐）**：分档管理——
  - `P0` / `P1`：不自动清，但每次更新必须重新确认是否仍有效；
  - `P2` / `P3`：超过 3 天未动，自动降级或删除；
  - 完成即从待办移除，不再保留「待验证」；
  - 待办总数上限 20 条，超限先清最旧。
  - 好处：待办永远反映真实待办。坏处：可能误删仍记挂的小事（已在进度节留痕）。
- **2B**：只清 P3，其余不动。
  - 好处：保守。坏处：P1 旧项仍堆积（即现状）。

### 机制 3：记忆固化，明确「升级路径」

- **3A（推荐）**：三段固化——
  - 降级 / 删除：`[当日]` 或 `P3` 条目，7 天未被引用 → 删；
  - 升级为长期：某条经验被引用 / 验证 ≥ 2 次 → 标 `[长期]`，跨天优先迁移；
  - 固化为规则：反复验证为真的教训 → 写入 `rules/` 或 `memory/error-notebook.md`，不再留在日记。
  - 好处：经验真正沉淀，日记保持精简。坏处：每次更新需做一次评估，略增开销。
- **3B**：只做升级，不做删除。
  - 好处：不丢信息。坏处：文件持续膨胀。

### 机制 4：跨天迁移，强制重新评估

- **4A（推荐）**：新建当日文件时，昨日待办逐条重评——仍有效的迁、已解决的删、P2/P3 超期的丢；禁止无脑整段搬运。
  - 好处：防止旧包袱滚雪球。坏处：无。

### 机制 5：文件上限与归档

- **5A（推荐）**：单文件仍为 300 行上限；`## 当前进度` 节超 150 行时，把已完成项归档到 `memory/archive/YYYY-MM.md`，正文只留活跃内容。
  - 好处：主文件永远短小。坏处：多一个归档目录。

## 三、待定项

### 6：长期经验固化到哪里

- **6A**：写入 `rules/`（成为强制规则，每次对话都加载）。
- **6B**：写入 `memory/error-notebook.md`（错题本，卡住时才翻）。
- **6C（推荐）**：按性质分——教训类进错题本，偏好 / 约束类进规则。

## 四、审批方式

回复五个机制的编号（如「1A 2A 3A 4A 5A」，或「全 A」）加第 6 项。
在收到审批前，不改动任何规则或记忆文件。
