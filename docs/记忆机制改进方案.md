# 记忆机制改进方案（定稿·待审批）

> 状态：**定稿**。本文档只描述拟议方案，未改动任何规则文件。
> 审批方式：确认整份方案后进入实施。

---

## 一、目标

当前记忆以 Markdown 文档承载，依赖 AI「自觉」去读、去写、去遵守。本方案把记忆改造为**可被程序操作的结构化系统**：启动时加载进内存，通过接口读写，规则由程序执行而非软遵守。

三条设计主线：

1. **结构化**：记忆不再是纯文本，而是带类型、时间、关键词、分级的节点网络。
2. **接口化**：记忆的读写、检索、分级、固化，全部通过接口完成。
3. **程序化**：可机械判定的规则由程序强制，语义性规则仍由 AI 判断，二者分层。

---

## 二、总体架构：三层记忆

```
第三层·事件层   用户发言为根 → 语义聚类成事件进化史 → 跨树突触关联
                    ↑ 由蒸馏层的精华喂养
第二层·蒸馏层   从每个节点提取「结论 / 进度 / 关键词」
                    ↑ 从消息树节点抽取
第一层·原始层   消息树（msgTree 边表 + 节点）——唯一权威存于后端 SQLite
```

**关键原则**：上层可随时回下层取原始措辞。蒸馏**不覆盖**原始内容，只在其上叠加。原始内容永久保留。

---

## 三、第一层：消息树迁入数据库

### 3.1 现状

抽屉消息树目前存在浏览器本地存储 `chrome.storage.local`，键为 `aiMirrorConv_<siteKey>__<convId>`，会话对象含 `msgTree`（边字典）、`visibleKeys`、`branchKeys`、`externalCards`、`orphanSlice`。

- `msgTree` 键为 `'父id-子id'`，值为节点，根用哨兵 `0`
- 节点为 `{ role, name, blocks, source, deleted, cards }`
- `source` 取 `user` / `assistant` / `tool`
- 树天然支持分支（重新生成=补新出边）与软删除（节点保留、树不断裂）

### 3.2 存储权威：后端唯一权威

- 消息树的**唯一权威存储**为后端 SQLite 数据库。
- **浏览器不再持久化消息树**：`chrome.storage.local` 不再保存 `msgTree` 及会话数据，扩展层全部改为**向后端查询**。
- 本地内存仅保留当前会话的**运行时视图**，页面刷新即从后端重新拉取。
- 后端不可达时，扩展无法读取历史——这是「单一权威」的必然代价，接受。

### 3.3 表结构

```sql
-- 节点表：对应 msgTree 的 value
CREATE TABLE nodes (
    id          INTEGER PRIMARY KEY,
    msg_id      TEXT UNIQUE,      -- 消息指纹（role+name+blocks 摘要）
    conv_id     TEXT,             -- 会话 id
    site_key    TEXT,             -- 站点
    parent_id   INTEGER,          -- 父节点（哨兵根为 0）
    source      TEXT,             -- user | assistant | tool
    role        TEXT,
    name        TEXT,
    blocks      TEXT,             -- JSON：完整内容块（无损，永久保留）
    deleted     INTEGER DEFAULT 0,
    -- 以下为蒸馏层字段，初始为空
    essence     TEXT,             -- 结论 / 进度摘要
    keywords    TEXT,             -- JSON 数组
    tier        TEXT DEFAULT 'temp',  -- temp | mid | perm
    hit_count   INTEGER DEFAULT 0,
    strength    REAL DEFAULT 0.5,
    created_at  INTEGER,
    last_hit_at INTEGER
);

-- 边表：对应 msgTree 的 key
CREATE TABLE edges (
    id             INTEGER PRIMARY KEY,
    src_node       INTEGER,
    dst_node       INTEGER,
    kind           TEXT,    -- parent_child | branch | associative
    weight         REAL DEFAULT 1.0,
    created_at     INTEGER,
    last_active_at INTEGER,
    UNIQUE(src_node, dst_node, kind)
);

-- 卡片表：对应节点的 cards（工具执行状态与结果）
CREATE TABLE cards (
    id          INTEGER PRIMARY KEY,
    node_id     INTEGER,
    block_id    TEXT,
    tool        TEXT,
    status      TEXT,
    result      TEXT,       -- JSON：工具结果
    finished_at INTEGER
);

-- 计划暂存表：双接口 A 专用（见第六节）
CREATE TABLE plans (
    plan_id    TEXT PRIMARY KEY,
    session_id TEXT,
    text       TEXT,
    created_at INTEGER
);

-- 修订日志表：语义修订只追加不覆盖
CREATE TABLE revision_log (
    id         INTEGER PRIMARY KEY,
    node_id    INTEGER,
    old_text   TEXT,
    new_text   TEXT,
    reason     TEXT,
    created_at INTEGER
);
```

索引：`nodes(conv_id, site_key)`、`nodes(parent_id)`、`edges(src_node)`。

向量检索用 `sqlite-vec` 扩展，关键词检索用 FTS5，同库运行，无需独立进程。

### 3.4 迁移方案

一次性迁移：把浏览器本地已有的会话存档全部推送至后端，之后只走后端。

**迁移补丁**：在**切换会话时**执行迁移（挂载点：会话切换入口）。逐会话检查——若后端无该会话记录，则从本地存档读取并推送一次；完成后标记该会话已迁移，避免重复。

> **临时代码标记**：此迁移补丁为过渡用。全部会话迁移完成、确认后端数据完整后，须删除该补丁。**此条已记入工作记忆，届时提醒删除。**

迁移失败处理：单会话迁移失败只记录并跳过，不阻塞切换；下次切换该会话时重试。

## 四、第二层：蒸馏管道

### 4.1 触发时机

**异步**：消息入树后丢后台线程蒸馏，不阻塞入树与上报。复用现有上报管线（入树 → `reportToBridgeWithMd` → bridge report → web_mirror）作为挂载点。

### 4.2 提取规则（按来源）

| 来源 | 原始内容（blocks，永久保留） | 蒸馏产出（essence） |
|---|---|---|
| user | 原句全文 | 请求 / 决策 / 偏好（保留原句，蒸馏版作影子） |
| assistant | 原句全文 | 结论、进度（剔除寒暄与过程描述） |
| tool | 原句全文 | 工具名 + 结果摘要 |

### 4.3 关键词提取：规则过滤 + 轻量 LLM 精筛

关键词是检索质量的根本，必须与任务强相关。流水线依次执行：

1. **规则初筛**：按词性（只保留名词短语、专有名词）、停用词表、TF-IDF 阈值过滤，剔除动词、形容词、泛化词。零 LLM 调用，快。
2. **LLM 精筛**：把初筛候选与当前任务上下文一并交给轻量 LLM，由它挑出**与任务强相关**的关键词，剔除同义泛词、领域无关词。一次额外调用，换取精度。
3. **计划锚定校验**：最终关键词须与接口 A 暂存的计划原文吻合，逐字比对（见第六节）。
4. **跨计划去噪**：某关键词在近期计划中出现频率超过阈值（如 80%）时自动降权——区分度太低。

### 4.4 分级与衰减

每个节点有强度 `strength`（0～1），公式：

```
node_decay_rate = base_decay / (1 + 0.1 × Σ(关联边权重))
strength = tier_base × (1 + 0.3 × log2(1 + hit_count)) × 2^(-days_since_last_hit / node_decay_rate)

tier_base：temp=0.3   mid=0.6   perm=1.0
```

突触（关联边）参与衰减：节点周围强边越多，衰减越慢，符合「突触越强、记忆越持久」的生物模型。

初始分级：用户发言 → `perm`；AI 回复 → `temp`；工具结果 → `mid`。

自动升降级：

| 迁移 | 触发条件 |
|---|---|
| temp → mid | `hit_count ≥ 3` 且 `strength ≥ 0.6` |
| mid → perm | `hit_count ≥ 10` 且 `strength ≥ 0.8` |
| perm 降级 | 不发生，除非用户显式删除 |

## 五、第三层：事件层

### 5.1 事件树

- 每句用户发言（`source='user'`）是一个**根节点**。
- 其触发的 AI 回复、工具结果作为子节点，`parent_id` 指向根。
- 跨会话「讲同一件事」的发言，语义聚类成一个**事件**，类内按时间排序成叙事线程。

### 5.2 突触关联

**建边规则**（新节点写入后执行）：

```
若 新节点.关键词 ∩ 旧节点.关键词 的大小 ≥ 3
且 交集 / 并集 ≥ 0.3
则 建立 associative 边，初始权重 = 交集大小
```

**强化规则**：两节点在同一次检索中被同时命中，边权重饱和式增长：

```
edge.weight += 0.2 × (1 - edge.weight)   // 上限 1.0
```

**衰减规则**：边 30 天未激活，权重减半；权重 < 0.1 标记 `dormant`（不删，但图遍历不展开）。

### 5.3 全自动 + 三条护栏

事件层全自动运行（自动聚类、建突触、合并），但必须带三条护栏防止语义漂移：

1. **边界锚定**：AI 判断的主题边界，必须同时存下触发边界的**原始语句**，供回溯。
2. **语义化延迟**：先存原句，语义摘要作为**影子节点**挂在其上。检索优先返回原句。
3. **修订留痕**：任何语义修订（合并、泛化、重写）写入 `revision_log`，只追加不覆盖。

## 六、防幻觉检索：双接口互锁

### 接口 A：计划锚定

```
memory_plan_submit(plan_text, session_id) -> plan_id
```

纯写入，把任务计划原文存入 `plans` 表，返回 `plan_id`。不检索、不推理、不调 LLM，毫秒级返回。

### 接口 B：验证式关联搜索

```
memory_search(plan_id, keywords, focus="relevance", top_k=10) -> [MemoryHit]
```

内部强制三步，顺序固定：

**第 1 步·锚定验证**：逐字比对，关键词必须存在于接口 A 的计划原文中，不在的拒绝并标注。

**第 2 步·三路并行检索**：FTS5 精确匹配 + 向量语义近邻 + 图遍历（沿边扩一跳）。

**第 3 步·交叉验证 + 融合**：RRF 融合三路排名，再乘关键词交集置信度（Jaccard 系数）压低语义漂移结果；`focus` 决定最终排序（`time` / `strength` / `relevance`）。

**防幻觉原理**：关键词必须先在计划原文中验证存在，才能进入检索；输入关键词越多，通过验证的越少但越硬，交集置信度越高，噪声被压得越狠。

## 七、记忆接口清单

**读写层**
- `memory_get(node_id)` — 按 id 取节点
- `memory_set(node_id, content)` — 更新节点
- `memory_delete(node_id)` — 软删除
- `memory_list(conv_id, prefix)` — 列举节点
- `conversation_get(conv_id, site_key)` — 取整个会话的消息树（浏览器走后端查询用）
- `conversation_put(conv_id, payload)` — 写会话消息树

**检索层**
- `memory_plan_submit(plan_text, session_id)` — 计划锚定（接口 A）
- `memory_search(plan_id, keywords, focus, top_k)` — 验证式关联搜索（接口 B）

**分级层**
- `memory_promote(node_id)` — 手动升级
- `memory_strength(node_id)` — 查询当前强度
- `memory_decay_run()` — 触发一次衰减计算

**事件层**
- `event_tree_get(root_id)` — 取某事件树
- `event_merge(candidate_ids)` — 合并事件
- `event_history(root_id)` — 取事件演化史

**固化层**
- `memory_promote_to_rule(node_id)` — 把反复验证的经验升级为规则
- `memory_promote_to_notebook(node_id)` — 写入错题本

**可视化**
- `graph_export(filter)` — 导出图数据（供 D3 渲染）

## 八、可视化

D3.js v7，两个视图：

1. **力导向全景图**：节点大小映射 `strength`，颜色映射 `tier`（临时=灰、中期=蓝、永久=金），边按 `kind` 着色（树边=实线灰、突触边=虚线彩）。
2. **径向树视图**：以某个用户发言为根，向外辐射其关联节点。

数据从 `graph_export` 接口以 JSON 返回。

## 九、规则程序化边界（诚实说明）

程序能强制的是**可机械判定的规则**，例如：

- 提交前必须回读文件 → 检查工具调用序列
- 不得清空真实数据 → 扫描破坏性接口调用
- 输出中出现禁用词 → 关键词扫描告警

程序**无法**强制**语义性规则**，例如「不得捏造用户发言」「先改写再回答」——这些仍需 AI 判断，程序只能做注入强制与输出审计。

因此规则程序化**按可判定程度分层**，不是全有或全无。

## 十、实施顺序：三层一次交付

三层（原始层迁移 + 蒸馏管道 + 事件层）作为一个整体工程一次交付，不拆期。

实施步骤：

1. **建库**：创建 SQLite 表结构、索引、`sqlite-vec` 与 FTS5 扩展。
2. **迁移与切换**：写迁移补丁（挂切换会话入口），把浏览器历史推入后端；扩展层改为全部走后端查询。
3. **接口层**：实现第七节全部接口。
4. **蒸馏管道**：接上报管线，异步蒸馏 + 关键词三层流水线。
5. **事件层**：语义聚类、突触建边、三条护栏。
6. **可视化**：D3 力导向图 + 径向树。
7. **规则程序化**：先落可机械判定的部分。

**风险提示**：三层一次交付工程量较大，联调链路长。若中途需回退，以「迁移补丁」为界——补丁未删时，浏览器本地数据仍在，可回退到本地存储方案。

## 十一、最终决策摘要

| 决策项 | 选定 | 说明 |
|---|---|---|
| 存储权威 | 后端唯一权威 | 浏览器不再持久化消息树，全部走后端查询 |
| 旧数据迁移 | 一次性迁移 | 切换会话时执行，补丁为临时代码，用后删除 |
| 蒸馏触发 | 异步 | 入树后后台线程蒸馏，不阻塞 |
| 事件层自动化 | 全自动 | 程序自动聚类/建突触/合并，带三条护栏 |
| 原始层保留 | 永久保留 | blocks 无损保存，只降级不参与主检索 |
| 关键词提取 | 规则 + LLM 精筛 | 规则初筛 → LLM 精筛 → 计划锚定 → 跨计划去噪 |
| 实施顺序 | 三层一次交付 | 以迁移补丁为回退边界 |
