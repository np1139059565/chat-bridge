## 背景

代码走查发现前端测试覆盖严重不足：

- 前端 JS：71 个文件、约 14029 行。
- 前端测试：仅 1 个文件、10 个用例，只覆盖 `web_bridge/web_logic.js`（78 行、4 个纯函数）。
- 覆盖率约 0.5%，且已证明「抽出纯逻辑 + node 测试运行器」这条路走得通，只是未扩大。

## 任务总览

1. **为 `extend/lib/dom-utils.js` 补测试**：覆盖 `hashStr` / `toArray` / `messageFingerprint` 等高频基础逻辑。
2. **为 `extend/dialog/parts/05f_parse.js` 补测试**：覆盖 JSON 控制字符修复、语音块提取、消息来源判定等历史 bug 高发区。
3. **确认 node 测试运行器已覆盖新增测试**：pre-commit 钩子能真正守住前端。
4. **合并 `host_theme.js` 重复**：`extend/lib/host_theme.js` 与 `skills/debug_chrome/extension/shared/host_theme.js` 两份。

## 已确认的决策

- 顺序：先建进度文档 → 补 dom-utils 测试 → 补 05f_parse 测试 → 验证钩子覆盖 → 合并 host_theme → 每步提交。
- 测试用 node 自带测试运行器（`node --test`），与现有 `tests/js/test_web_logic.test.js` 一致。
- node 便携版路径：`D:\mydata\tools\node-v20.18.0-win-x64\node.exe`。

## 关键事实（探查所得，避免重复探查）

- 前端测试钩子：`scripts/hooks/check_js_tests.py`，已接入 `.pre-commit-config.yaml`。
  它用 `node --test flask_server/tests/js/` 运行，node 缺失时跳过。
- `dom-utils.js` 是 IIFE `(function(global){...})(typeof window!=='undefined'?window:this)`，
  无 `module.exports`。node 下 `this` 指向 `module.exports`，故 `require` 后取 `module.exports.*` 可达。
- `05f_parse.js` 依赖 `window.AIMirrorDialog`（methods 命名空间）与 `window.AIMirrorDomUtils`，
  在 node 下需先构造这两个全局桩再加载。
