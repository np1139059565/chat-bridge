## 何时使用此技能

当需要执行以下任意一类代码管理任务时,使用此技能:

- 认证与 Cookie 管理（Gerrit API 的 Cookie 配置与失效更新）
- 编写述职报告（获取变更列表、查看变更、生成记录）
- 评审人管理（获取变更列表、搜索评审人、添加评审人、智能补充评审人）
- 代码走查与评论打分（查看变更、发表行内评论、发布评审并打分）
- Git 代码提交（提交代码、生成提交说明、分支管理）
- 其他 Git 操作（常用命令与辅助命令）

> **重要使用原则**  
> 必须根据用户要求在下文场景分类选择正确的执行方式。
> 必须严格按照场景所列的步骤顺序执行,严禁跳步或颠倒。
> **严禁在用户没有明确要求的时候使用 Git 操作/推送本地代码**。
> **严禁使用powershell命令行,必须使用cmd命令来执行**。

## 如何使用此技能

在执行任意代码管理任务前:

> **【命令执行环境约束 - 必读】**
> 本技能在自动化环境中运行,**每条命令都是独立 shell**,且**非 `cmd /c` 前缀的命令会触发 shell 初始化故障**(`无法启动此 shell。初始化过程中出现故障`)。因此:
> - 所有调用 Gerrit API 的 `curl` 命令**必须用 `cmd /c "..."` 包裹**;
> - **严禁使用 `set` 环境变量方案**:`set` 命令具有延迟性,与任何后续命令用 `&`/`&&` 连接必然失败;且每条命令都是独立 shell,`set` 的变量在下一条命令中必然丢失。因此 **Cookie 一律采用硬编码**——把完整 Cookie 字符串直接写进 `-H "Cookie: ..."`(详见 `examples/auth-cookie.md`),不要写 `set COOKIE=... & curl ... %COOKIE%`;
> - URL 中的 `&` 必须转义为 `^&`,否则命令被截断。

1. **识别任务类型**:从用户请求中判断属于哪一类操作(认证、评审人、代码走查、Git 提交、其他 Git 操作)。
2. **加载对应的规范文件**:从 `examples/` 目录读取对应的 guideline 文件,严格按其内容执行。
   - `examples/auth-cookie.md` - 认证与 Cookie 管理(Cookie 配置、失效更新)
   - `examples/reviewer-management.md` - 评审人管理(变更列表、搜索/添加评审人、智能补充)
   - `examples/code-review.md` - 代码走查与评论打分(变更详情、Diff、草稿、发布评审)
   - `examples/git-commit.md` - Git 代码提交(提交流程、提交说明、智能生成)
   - `examples/other-git-ops.md` - 其他 Git 操作(常用命令与辅助命令)
   - `examples/performance-report.md` - 述职报告生成(格式规范、Gerrit 为主本地 Git 为辅、严禁行数统计)
   - `examples/notes.md` - 注意事项(通用约束与安全要求)
3. **遵循文件中的具体指示**:格式、步骤、命令均以下方文件为准,严禁修改其中的规范内容。

若任务类型无法匹配上述任一文件,请向用户确认所需操作的具体类型。
